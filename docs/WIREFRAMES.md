# Wireframes

## 1. 问答页面

```text
+----------------------------------------------------------+
| geowiki                                                  |
+----------------------------------------------------------+
| 系统自动选择检索深度                         按实际路径计次 |
| 明确问题直接查证；复杂问题自动进入综合研究               |
+----------------------------------------------------------+
| [ 输入专业问题，例如：哪个标准规定了金矿基本工程间距？ ] |
|                                             [发送]       |
+----------------------------------------------------------+
| 答案                                                     |
| 根据当前知识库检索结果，...                              |
|                                                          |
| 引用来源                                                 |
| 1. 文件名称 / 条款号 / 页码                              |
|    原文片段...                                           |
| 2. 文件名称 / 条款号 / 页码                              |
|    原文片段...                                           |
|                                                          |
| 检索依据                                                 |
| 关键词: 5 条 | 向量: 8 条 | 直接证据: 3 条              |
|                                                          |
| [有用] [不准确] [复制答案]                               |
+----------------------------------------------------------+
```

自动进入综合研究后，答案位置显示：

```text
正在逐份检索候选文件                              57%
[==============================----------------------]
已审查 21/31 份                         证据覆盖 7 份
```

## 2. 页面元素

- 顶部标题
- 问题输入区
- 答案区
- 引用来源区
- 检索依据区
- 用户反馈区
- 会话历史入口
- 自动检索深度说明和实际路径配额成本
- 深度任务阶段、进度、候选覆盖和刷新恢复

## 3. MVP 交互

1. 用户输入问题并点击发送，不需要预判问题复杂度。
2. 后端统一完成问题理解、歧义判断和路径选择。
3. 明确问题显示直接查证加载状态；复杂问题自动创建持久化研究任务并显示阶段和进度。
4. 后端返回直接答案，或在研究任务完成后返回比较矩阵与覆盖范围。
5. 页面展示答案、短引文、官方链接和按实际路径结算的配额。
6. 用户点击反馈。

## 4. 管理员反馈队列

- 展示反馈时间、原问题、原因、补充说明、用户、处理通道和状态。
- `wrong_standard`、`wrong_clause`、`missing_evidence` 标记为知识库审核，不直接修改正式知识库。
- 管理员可更新为待处理、处理中、待 KB 审核、已解决或已忽略，并记录处理说明。
- 回答反馈可转为领域词典候选，保留原问题和反馈编号作为来源。

## 5. 管理员领域词典

- 侧栏提供独立“领域词典”入口，仅管理员可见。
- 页面分为审核队列、正式词条和审核记录，并显示启用、待审核、停用和高风险数量。
- 候选编辑器提供规范映射、独立运行开关、上下文、检索/证据约束、正例、反例、风险和审核记录。
- 上线前预览对比当前与候选规则；正反例未全部通过时不能批准。
- 正式词条只能提修改候选，不能直接覆盖；停用和恢复必须填写原因。
